# v1.4.10：修复 DSH 0.2.2 上的自动审查

DSH 0.2.2 改了官方自动审查的请求格式，本版让插件重新接管审查，并去掉会失败的 temperature 参数。

- **自动审查在 DSH 0.2.2 上恢复**：0.2.2-rc.2 仍用固定的 `REVIEW_POLICY` 系统提示，但用户消息从 0.2.1 的一条四段 JSON（ENVIRONMENT、PROJECT_INSTRUCTIONS、FILTERED_HISTORY、PENDING_ACTION）改为「第一条是环境，之后每条消息一个会话条目，最后一条是待审工具调用」。1.4.9 只认旧格式，在 0.2.2 上会把每次审查原样交给会话模型，设置里选的 Jev 或 DeepSeek Flash 实际没有生效。现在按系统提示识别官方审查，两种格式都读；读不懂的新格式会让这次审查失败（官方因此拒绝调用），不会再悄悄换成会话模型。Jev 的判断状态也改用 0.2.2 的条目（`user-instruction` 等角色、工具 schema、待审调用的参数）。
- **审查请求不再带 temperature**：官方审查请求带 `temperature: 0`，但 `gpt-6.1-terra` 和 `gpt-5.6-sol` 会以 `Unsupported parameter: temperature` 拒绝整次审查（DeepSeek 接受）。现在 PackyCode 线路会在官方审查请求上丢掉这个字段，所以审查模式选「跟随对话模型」时也不会因此失败；普通对话请求不受影响。
- **其余行为不变**：审查规则、放行或拒绝后的处理仍由 DSH 官方插件决定；模型列表、图片、网页搜索、Claude 通道和 Key 轮换都保持原样。

验证：576 项测试、两份构建和发布包检查通过。用测试 Key 实测 `scripts/live-check.mjs`：0.2.1 和 0.2.2 两种审查请求都由 `jev-1.14.0` 和 DeepSeek Flash 正确回答，8 次判定全部符合预期（1.3 到 2.6 秒）；其余目录模型正常，只有 `gemini-4-argon` 被 Google 上游以 `Publisher model ...` 拒绝，与本次改动无关。`gpt-6.1-terra`、`gpt-5.6-sol` 带 temperature 的 400 已单独复现；桌面应用里的 0.2.2 全流程尚未实测。

在 DSH 插件管理中更新至 **1.4.10**，然后重新打开 DSH 加载新版。
