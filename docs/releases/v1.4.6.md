# v1.4.6：新增腾讯混元 Hy4

模型列表新增腾讯混元 Hy4（`hy4`），需要 Key 的分组包含 PackyCode 新开的 `hunyuan-officially`。

- **Hy4**：走 Responses 协议，可带图，1024K 上下文（输入最多 960K），最多输出 64K。在模型选择器里排在 Grok 4.7 之后；设置页每个 Key 下多了一行 Hunyuan，能看出这个 Key 能不能用 Hy4。
- **推理档位只有关和 `high`**：按腾讯云 TokenHub 文档，Hy4 只支持 `high` 和 `no_think` 两档，默认开启思考，关闭推理时插件发送 `no_think`。网关虽然也接受 `low`、`medium` 等档位，但 Hy4 的文档里没有，实测效果也和 `high` 看不出区别，所以不提供。会话标题由 Hy4 自己在关闭推理时生成。
- **推理会原样带回**：按 TokenHub 的要求，工具调用续接时和之后的每一轮，都会带上 Hy4 之前的推理。前缀缓存不需要额外字段就能命中。
- **Hy4 不再自称 DeepSeek**：DSH 的系统提示词只写了「powered by DeepSeek Harness」和模型代号 `hy4`，Hy4 会因此说自己是 DeepSeek 的模型，还否认自己是混元。现在插件在 Hy4 每个请求的系统提示词末尾补一句说明：它是腾讯混元的 Hy4，经 PackyCode 接入，DeepSeek Harness 只是运行它的应用。其它模型的请求不受影响。

验证：557 项测试、两份构建和发布包检查通过，在 Node 22 下也通过。直连网关确认了 Hy4 各档位、输出上限、缓存和工具参数的实际表现。通过插件实测：关闭推理和 `high` 都正常回答，其余档位在发出请求前就被拒绝；工具调用在两个档位下都能续接，下一轮仍带着之前的推理；会话标题正常；红、蓝两张图片都能认对，不过 `high` 下 Hy4 有时会在纯色图上推理过长，被实测脚本 2,048 token 的输出上限截断。加上身份说明后，带着 DSH 的系统提示词问身份，Hy4 每次都说自己是腾讯混元。全模型实测中只有 `gemini-4-argon` 没有回答：PackyCode 现在只把它列在 `gemini-officially` 分组，测试 Key 没有这个分组，插件这边没有改动。新版本尚未在 DSH 桌面端完整验证。

在 DSH 插件管理中更新至 **1.4.6**，然后重新打开 DSH 加载新版。
