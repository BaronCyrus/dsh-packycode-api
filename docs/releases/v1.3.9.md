# v1.3.9：更新失败时说明原因

点「更新插件」失败时，如果是安装源还没同步新版本或者连不上，设置页会直接说明，不再只显示「更新失败」。

- **安装源还没同步**：插件从 npm 读到新版本号，DSH 的 pnpm 却从 profile 配置的安装源下载。刚发布的版本，安装源可能还没同步：1.3.8 发布 36 分钟后，npmmirror 仍然只有 1.3.7；npm 自己的 CDN 也可能在几分钟内对新包返回 404。以前这时只显示「更新失败，请重试，或在插件页重新安装。」，现在会写明是哪个安装源还没同步，请你过几分钟再更新。
- **连不上安装源**：pnpm 连不上安装源（域名解析失败、连接被拒、连接重置或超时），或者安装超过 3 分钟还没结束，会提示检查网络或代理后重试。
- **其他情况不变**：其他原因的失败仍显示原来的提示，插件也不会自动切换安装源。页面上只显示安装源的域名，地址里的路径、凭据和 pnpm 的输出都留在 Host 端。
- **超时不再被当成普通失败**：以前 pnpm 卡住、被插件按时结束后，Node 先报出自己的中止错误，「超时」这个原因就丢了，结果只显示笼统的失败。现在会正确提示连不上安装源。

验证：515 项测试、两份构建和发布包检查通过。用 DSH 自带的 pnpm 11.28.5 在装有 1.3.7 的临时 profile 中实测：官方源正常更新到 1.3.8；npmmirror（当时还没有 1.3.8）0.9 秒内提示还在同步；连接被拒的源在 pnpm 自己重试完后（约 70 秒）提示连不上；不回包的源到时间上限时提示连不上（测试时上限设为 20 秒），profile 没有改动，也没有残留的 pnpm 进程。提示文字通过界面测试检查，新版本尚未在 DSH 桌面端界面中验证。

在 DSH 插件管理中更新至 **1.3.9**，然后重新打开 DSH 加载新版。
