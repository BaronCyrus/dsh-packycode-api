# v1.4.8：新增 Claude Fable 5.2 和 MiniMax H3 图片模型

模型列表新增 `claude-fable-5-2`，图片生成与编辑新增 MiniMax H3 Image 两款型号，图片设置里能看到每个图片 Key 的分组。

- **Claude Fable 5.2**：`claude-fable-5-2` 排在 Claude 模型的第一位，1M 上下文、128K 输出，思考不能关，档位为 `low` 到 `max`。`cc` 分组的 Key 由本机 Claude Code CLI 完成会话，其它 Claude 分组走 HTTP；会话标题由 `claude-haiku-5-5` 生成。
- **MiniMax H3 Image**：图片型号新增 `MiniMax-H3-Image` 和出图更快、单价更高的 `MiniMax-H3-Image-Highspeed`，生图和编辑都支持。它们没有质量档位，设置里只有「自动」；不支持透明背景和 mask，带这两项的请求会在发出前被拒绝。不指定尺寸时按 2K（约 400 万像素）出图，比例由模型决定，也可以在对话里指定尺寸。这两款在 PackyCode 只开给 `image` 分组。
- **图片 Key 的分组**：图片设置在每个图片 Key 下显示它的分组，型号列表只列出当前使用的 Key 支持的型号，并说明哪些型号因分组不支持而隐藏。已保存的型号若不被当前 Key 支持，会保留在列表里并给出警告和所需分组，不会自动改成别的型号。
- **分组不支持时的提示**：图片 Key 的分组不提供所选型号时，生图工具会直接说明原因，并要求不要换型号重试，改由你在设置里选型号或换 Key。

验证：569 项测试、两份构建和发布包检查通过，在 Node 22 下也通过。用 `cc` 分组的 Key 通过 Claude Code CLI 实测 `claude-fable-5-2`，只读查询、编辑、拒绝删除、计划模式、提问、看图和标题 7 项全部通过，没有客户端异常拒绝。用 `image` 分组的图片 Key 实测 6 次请求全部成功：两款 MiniMax 型号在 `1024x1024` 下生图和编辑都正常，`MiniMax-H3-Image` 不指定尺寸时生图和编辑都返回 2048×2048，耗时 8 到 26 秒；图片 Key 的分组读取返回 `image`，五个图片型号都判为可用。`claude-fable-5-2` 的 HTTP 通道没有实测（没有 `cc-sale`、`cc-expensive` 或 `claude-officially` 分组的测试 Key）；MiniMax 的 4K 档、多张参考图的编辑没有验证；图片设置的新界面只通过构建产物的测试验证，尚未在 DSH 桌面端实际查看。

在 DSH 插件管理中更新至 **1.4.8**，然后重新打开 DSH 加载新版。
