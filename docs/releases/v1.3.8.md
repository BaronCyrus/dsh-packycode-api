# v1.3.8：自动审查可改用 jev-latest 或 DeepSeek Flash

开启 DSH 自带的「自动授权审查」后，权限菜单里的「自动审查」可以改用 PackyCode 的 jev-latest 或 DeepSeek Flash 审查每次工具调用，审查规则和处理方式保持官方原样。

- **自动审查可换审查模型**：DSH 自带的实验插件「自动授权审查」默认关闭，在左侧「插件」页开启后，权限菜单里会多出「自动审查」。每次工具调用前先由模型审查：放行的直接执行，拒绝的改为请你批准。它默认用当前对话的模型；现在可以在「设置 → PackyCode → 自动审查」改成 jev-latest（默认）、DeepSeek Flash，或保持跟随对话模型。审查看什么、按什么规则、放行和拒绝后怎么处理，仍由官方插件决定，本插件只替换回答审查的模型。
- **接入 jev-latest**：TypeSafe 的决策分类模型，走 PackyCode 的 `/v1/systemone`（`typesafe-officially` 分组）。它不能对话，所以不在模型选择器里。插件把官方的审查内容和规则原文交给它，再把结果换算成官方要求的放行或拒绝答复；一次约 0.4 秒，只按输入计费。「账户与 Key」里每个 Key 会显示能否调用 Jev。
- **DeepSeek Flash 审查**：官方的审查请求原样改发到 PackyCode 的 DeepSeek Flash，一次约 2 秒，拒绝时写明原因。
- **设置卡片**：显示官方插件是否已开启及开启方法、所选审查模型、本插件处理过的审查次数（放行 / 拒绝 / 失败）和最近一次结果；没有 Key 能调用所选模型时会提示。权限菜单里「自动审查」的说明文字仍是 DSH 的「由同一模型审查」，实际以设置为准。

验证：510 项测试、两份构建和发布包检查通过。用官方的审查请求格式和官方解析器在 37 个场景上实测，两个审查模型在 35 个有明确答案的场景上全部符合预期（jev-latest 中位 0.35 秒，DeepSeek Flash 中位 2.3 秒）。在开启官方插件的临时 DSH 0.2.1-rc.2 中实际发起强推：三种设置分别由 jev-latest、DeepSeek Flash 和对话模型审查，官方插件据此发起审批。十个模型、Key 轮换、失败分类和新增的审查检查实测正常。新版本尚未在 DSH 桌面端界面中验证。

在 DSH 插件管理中更新至 **1.3.8**，然后重新打开 DSH 加载新版。
