# v1.3.4：cc 分组的 Claude 走官方 CLI，并适配 DSH 0.2.1

`cc` 分组的 Key 发 Claude 请求时改由本机官方 Claude Code CLI 发出；插件同时适配 DSH 0.2.1。

- **cc 分组走官方 CLI**：PackyCode 的 `cc` 分组只接受官方客户端，这类 Key 的 Claude 请求改由本机的 Claude Code CLI 发出；`cc-sale`、`cc-expensive`、`claude-officially` 等分组照旧走插件内 HTTP。CLI 只负责传输：它自己的工具全部关闭，DSH 的工具经本机 MCP 桥提供给它，工具执行、权限审批、计划模式、附件和完整对话历史都和其他模型一致。
- **Claude Code CLI 设置卡片**：在 **设置 → PackyCode → Claude Code CLI** 可以查看安装状态和版本、一键安装 CLI，并为 Claude 选择通道：按分组（默认）、始终用 CLI 或始终用 HTTP。「账户与 Key」里每个能用 Claude 的 Key 都会标出走 CLI 还是 HTTP。使用 `cc` 分组的 Key 前，请先在这里安装 CLI。
- **适配 DSH 0.2.1**：DSH 0.2.1 要先确认有可用 Key 才列出模型，所以没有 Key 时不显示 PackyCode 模型，添加 Key 后会自动出现。存了多把 Key 时，模型列表不再等待分组读取（以前最多要等约 6 秒）。另修复：在 DSH 0.2.1 下，Haiku 和 Sonnet 第一轮带工具的请求如果被网关误拦（提示客户端异常或不要发测试消息），会重新照常自动重试一次。
- **兼容声明**：插件依赖声明加入 cordis 4.0.5 和 pi-ai 1.1.0，开发和测试改在 DSH 0.2.1-rc.2 的宿主包上进行。
- **发布节奏**：新版本先发布到 npm 的 `next` 标签，约 25 小时后才成为 `latest`。急用可以在插件页填写精确版本 `dsh-packycode-api@1.3.4` 提前安装。

验证：456 项测试、两份构建和发布包检查通过，并在 DeepSeek Harness 0.2.1-rc.2 自带的宿主包上重跑了全部测试。实测：十个模型、Key 轮换与设置页接口均正常；用 `cc` Key 经官方 Claude Code CLI 2.1.295 对 Opus、Sonnet、Haiku 各做文本、工具调用、图片、会话标题和计划模式检查，15 项全部通过；维护者也已在本地 DSH 0.2.1 中试用。

在 DSH 插件管理中更新至 **1.3.4**，然后重新打开 DSH 加载新版。
