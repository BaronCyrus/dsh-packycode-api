# v1.4.0：cc 分组的 Claude 会话改由 Claude Code 自己完成

`cc` 分组 Key 的 Claude 会话改由本机的 Claude Code 当 agent，修复“客户端存在异常”的拒绝；DSH 负责工具卡片、授权、计划审阅和提问。

- **修复“客户端存在异常”**：PackyCode 的 cc 分组按请求内容判断是不是 Claude Code 自己在工作。1.3.4–1.3.9 借官方 CLI 发出的是 DSH 的系统提示词和工具，带工具的请求大约一半被判为客户端异常，换编码类任务时第一个请求就被拒；更新 CLI 也没用。现在 Claude Code 用它自己的系统提示词和工具做事，和 paseo 等工具使用官方 CLI 的方式一样；DSH 为自己的 agent 附加的内容（`AGENTS.md`、运行环境、时间、技能列表和各类提示）也不再交给它，它只收到你发的消息。在三个 Claude 模型上实测，这样的请求没有再被拒。
- **工具调用显示成卡片，授权由 DSH 决定**：Claude Code 的每次工具调用都显示成 DSH 的工具卡片（命令是终端卡片，改文件是 diff）。它请求授权时，按会话的权限预设处理：`workspace-write`（默认）下工作目录内改文件直接进行，非只读命令等操作会弹出 DSH 的授权提示；`read-only` 下改文件也要授权；`auto` 下交给自动审查，审查拒绝时再问你；`danger-full-access` 下不询问。你拒绝时，理由会原样告诉 Claude Code。
- **计划模式和提问在 DSH 里完成**：`/plan` 后 Claude Code 进入它自己的计划模式，写好计划后交给 DSH 的计划审阅；批准后按预设继续，选「继续规划」时你的反馈会交给它修改。它向你提问时，问题出现在 DSH 的提问界面。
- **会话可以续接**：一个 DSH 会话对应一个 Claude Code 会话。进程空闲结束、DSH 重启、换模型或换 Key 后，都能接着原来的会话；编辑过历史消息或从别的模型切过来时，从 DSH 的历史新开一个。你在它工作时插话，插件会停下它当前的请求，把这句话作为下一条消息交给它。
- **分组读不到时先走 CLI**：插件还没读到 Key 的分组（刚启动、网络或代理不稳）时，Claude 请求先交给 Claude Code CLI：cc 分组的 Key 走 HTTP 一定被拒，而官方客户端各个 Claude 分组都接受；读到分组后，其它分组再改走 HTTP。一轮对话从 CLI 开始，就在 CLI 上做完。读取失败的 Key 约 30 秒后重读，不再等 10 分钟。
- **修复单分组 Key 读不出分组（#3）**：网关对只有一个分组的 Key 改用「分组 cc-sale 下模型 … 无可用渠道」的拒绝文案，插件现在也能从中读出分组。
- **需要注意的差别**：命令和文件修改由 Claude Code 在本机直接执行，不经过 DSH 的沙箱，只受上面的授权把关。DSH 自己的工具（子代理、todo、后台任务、生图、DSH 搜索等）在这些会话里不可用，Claude Code 用它自己的同类工具。项目里的 `CLAUDE.md` 会生效。`cc-sale`、`cc-expensive`、`claude-officially` 等其他分组不受影响。
- **报错说明更正**：cc 分组仍判定为客户端异常时，提示不再建议更新 CLI，而是说明这是按请求内容的判定，可以重发一次，反复出现时把原文发给 PackyCode 客服或改用其他分组的 Key。

验证：535 项测试、两份构建和发布包检查通过。用同一个 cc Key 实测：改动前，旧通道的 15 项检查失败 7 项；改动后，`claude-check --transport cli` 在 Opus、Sonnet、Haiku 上各跑 7 个场景，21 项全部通过。这 7 个场景是读文件计算、需授权的修改、被拒绝的删除、计划审阅后实施、提问、看图和起标题，共 53 个请求，没有一个被判客户端异常或反滥用。在无头 DSH 0.2.1-rc.3 里用真实 CLI 跑了 10 个任务：授权批准和拒绝、计划审阅（先要求修改一次再批准）、提问、换进程续接、自动审查放行和转问用户，都按预期完成。在 DSH 桌面端检查了读文件卡片、授权提示的批准和拒绝、`/plan` 计划审阅后实施、提问界面和重启后续接，都正常；这次检查发现并修掉了几个问题：分组读得慢时第一个请求走了 HTTP、桌面端 `/plan` 没有切到 Claude Code 的计划模式、DSH 的上下文消息被转给了 Claude Code、先用别的模型建的会话每轮第一步缺少镜像工具。CLI 2.1.259 与 2.1.295 都支持插件用到的授权和模式切换。`live-check` 中其他模型、Key 轮换、两种自动审查模型和设置页接口都正常；grok-4.7 被网关以分组不覆盖该模型拒绝，测试 Key 的 grok-officially 分组目前不提供它。

在 DSH 插件管理中更新至 **1.4.0**，然后重新打开 DSH 加载新版。
