# v1.3.7：GPT 网页搜索恢复可用

GPT 搜索后端改为流式读取，修复每次搜索都报 "returned no web_search_call" 的问题；Claude Code CLI 卡片在有新版本时也会提示更新。

- **GPT 网页搜索恢复可用**：PackyCode 的 Codex 通道对非流式 `/v1/responses` 请求返回 `completed`，搜索其实已经执行，但 `output` 为空，1.3.6 因此每次报 "PackyCode search returned no web_search_call"。现在 GPT 搜索改为流式，从 `response.output_item.done` 事件重建结果，来源和摘要的取法与以前相同。
- **上游临时满载时自动重发**：网关在流中转发的 "Temporary capacity limit"（`rate_limit_exceeded`）和 `server_error`，会按提示的间隔在同一个 Key 上最多重发两次，不会因此停用 Key；仍失败时，错误会注明模型并建议改用 DeepSeek 后端。流中的其它错误直接报出上游原话。
- **始终发送 `prompt_cache_key`**：Codex 分组会以 403（「请使用标准 Codex 客户端」）拒绝不带这个字段的请求。DSH 内的搜索本来就带会话 id，没有会话的调用方现在也会自带一个。
- **Claude Code CLI 有新版本时提示更新**：以前只有低于 2.1.259 的 CLI 才显示「更新 Claude Code CLI」。现在插件在本机读取 npm 上 `@anthropic-ai/claude-code` 的 `latest`（30 分钟内最多读一次，点「重新检测」立即重读，读不到时不提示），能用但不是最新版的 CLI 会显示新版本号和同一个按钮。
- **更新结果判断更准**：已经能用的 CLI 更新后版本没变、而又有更新的版本时，会显示安装器自己的输出（例如 Homebrew 的 `brew upgrade claude-code`），不再误报「已更新」。

验证：480 项测试、两份构建和发布包检查通过。实测 Codex 分组：非流式搜索 3 次都返回空 `output`，流式时结果全部在 `output_item.done` 事件里；28 次 GPT 搜索经新逻辑解析，每次得到 13–20 个来源和摘要，多数在 10–30 秒内完成（DSH 桌面版给网页搜索 60 秒）。十个模型、Key 轮换与失败分类实测正常，DeepSeek 搜索 6 秒返回；当时 GPT 搜索碰上上游满载，三次都未成功，按新格式报错。CLI 更新提示在临时目录中把 npm 安装的 2.1.295 更新到了 2.1.303。未在 DSH 桌面端实机对话验证。

在 DSH 插件管理中更新至 **1.3.7**，然后重新打开 DSH 加载新版。
