# v1.3.3：插件内更新不再导致其他插件装不上

修复：用「更新插件」升级后 24 小时内，在同一个 profile 里安装其他插件会失败（`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`）。

- **原因**：更新按钮安装新版本时关掉了 pnpm 的发布冷却检查，新版本没有被登记为例外。之后 DSH 再安装任何插件，pnpm 都会因为 lockfile 里这个“太新”的版本拒绝整次安装，直到它发布满 24 小时。
- **修复**：按钮改为遵守 profile 自己的 pnpm 策略。默认情况下照常立即更新，由 pnpm 自动登记例外；如果你给 pnpm 配了更严格的策略，按钮会提示什么时候可以更新，而不是报失败。
- **发布节奏**：新版本先发布到 npm 的 `next` 标签，约 25 小时后才成为 `latest`。在此之前，插件内更新和不带版本号的安装都看不到它；急用可以在插件页填写精确版本提前安装。
- **已经被卡住时**：在插件页带版本号重新安装一次当前的 PackyCode 版本（例如 `dsh-packycode-api@1.3.2`），pnpm 会补上例外，其他插件随即可以正常安装。

验证：401 项测试、两份构建和发布包检查通过。用 DSH 自带的 pnpm 在临时 profile 实测：默认策略下更新立即完成并自动登记例外，之后安装其他插件正常；严格策略下不安装，并给出可以更新的时间；已被旧按钮卡住的 profile 重新精确安装后恢复正常。全部十个模型、Key 轮换与设置页接口的实测检查均正常。未重启 DSH。

在 DSH 插件管理中更新至 **1.3.3**，然后重新打开 DSH 加载新版。
