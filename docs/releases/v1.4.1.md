# v1.4.1：cc 分组的会话标题恢复正常

修复 1.4.0 中 `cc` 分组 Key 的 Claude 会话标题变成 “Untitled Session”“Empty Session” 的问题：生成标题时，Claude Code 现在能看到要命名的对话了。

- **标题按对话内容生成**：DSH 生成标题时，把你发过的消息放进一条单独的消息交给模型，这条消息标的是 DSH 自己的来源，不是“用户”。1.4.0 起 cc 分组只把你本人发的消息交给 Claude Code，这条消息就被滤掉了，模型只能给一段空对话起名，标题于是成了 “Untitled Session”“Empty Session”“空白会话” 之类。现在标题请求原样交给 Claude Code；这条消息里只有你发过的话，不含 DSH 给自己的 agent 附加的内容。
- **长消息不再被截断**：以前每条消息只取前 2000 个字符，开了 DSH 实验性插件「随对话更新的标题」时，最新的几条消息会被截掉。现在和 HTTP 通道一样整段交给模型，长度由 DSH 自己限制（默认 4096 字节）。
- **测试改用 DSH 真实的标题请求**：测试和实测脚本以前把要命名的内容当成用户本人的消息发送，所以没发现这个问题；现在用的是从 DSH 0.2.1 标题插件原样拷来的请求。
- **已有的标题**：DSH 默认只在会话的第一条消息后生成一次标题，已经生成的错误标题不会自动更新，可以手动改名；开了「随对话更新的标题」的会话，发下一条消息时会重新生成。其他分组和其他模型不受影响。

验证：535 项测试、两份构建和发布包检查通过；新的标题测试在 1.4.0 的代码上会失败。用同一个 cc Key 和 Claude Code 2.1.295 实测 DSH 真实的标题请求：修复前，Opus、Sonnet、Haiku 三次全部失败，标题是 “Greeting”“空白会话”“空白会话”；修复后连跑三轮，9 次全部通过，标题如“仓库发货安排核对”“仓库发货安排与缺货采购”，没有请求被判客户端异常。新版本尚未在 DSH 桌面端验证。

在 DSH 插件管理中更新至 **1.4.1**，然后重新打开 DSH 加载新版。
