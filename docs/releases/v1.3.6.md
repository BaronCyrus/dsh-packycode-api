# v1.3.6：DeepSeek Flash 改走 Responses

DeepSeek Flash 改用 PackyCode 网关的 Responses 接口调用，推理档位、识图和工具调用照常可用。

- **DeepSeek Flash 走 Responses**：`deepseek-flash` 的请求从 `/v1/chat/completions` 改发到 `/v1/responses`，base URL 仍是 `https://cf.api.fan/v1`，需要的分组不变（`deepseek-officially`、`deepseek-sale`）。PackyCode 的模型目录已列出它支持 Responses。
- **推理档位不变**：仍可关闭，或选 `low` / `high` / `max`。关闭时发送 `reasoning.effort: "none"`，网关返回时不带思考；开启时思考内容实时显示，并随同一轮的工具调用一起回传给模型。
- **缓存与图片**：和 Grok 一样不发送 `prompt_cache_key`，前缀缓存照常命中；图片以 `input_image` 随请求发送。
- **旧会话可继续**：以前经 Chat Completions 聊过的 DeepSeek 会话可以直接接着聊，之前的思考内容会作为普通文字带上。
- **其它**：目录里已没有模型使用 Chat Completions，插件不再加载这套接口；读取 Key 分组的探测请求不受影响。

验证：461 项测试、两份构建和发布包检查通过。直接请求网关时，`deepseek-flash` 在 Responses 上各推理档位都返回 200，`none` 时不产生思考；输出上限 384,000 在网关允许的 393,216 以内。经插件实测四轮工具对话：`high`、`max`、关闭、混合档位以及多段思考回传都正常，不带 `prompt_cache_key` 也命中缓存，Chat Completions 开始的会话能在 Responses 上继续。十个模型、Key 轮换与设置页接口的实测均正常，DeepSeek 识图正确认出红、蓝两张图。未在 DSH 桌面端实机对话验证。
