# v1.4.9：自动审查改用 jev-1.14.0

PackyCode 下掉了 `jev-latest` 别名，自动审查改用版本号 `jev-1.14.0`，已保存旧值的设置仍然有效。

- **自动审查改用 `jev-1.14.0`**：PackyCode 的 `/api/pricing` 现在只在 `typesafe-officially` 分组里列出 `jev-1.14.0` 和 `jev-1.13.0`，不再有 `jev-latest`；实测请求 `jev-latest` 会在到上游之前被网关拒绝（`model_not_found`、`当前令牌未覆盖供应商`）。审查请求、Key 分组可达性、拒绝理由和失败提示都改用 `jev-1.14.0`，设置卡片里的审查模型也显示这个版本。
- **已保存的 `jev-latest` 继续可用**：插件 Config 仍识别旧值（直接删掉会让保存过该值的用户插件加载失败），读取时按 `jev-1.14.0` 审查；卡片不再提供旧别名，写回旧值会被拒绝。
- **其它功能没有变化**：模型列表、图片生成与编辑、网页搜索、Claude 通道和 Key 轮换都保持原样。

验证：570 项测试、两份构建和发布包检查通过。用仓库里的测试 Key 实测 `scripts/live-check.mjs`：分组读取能到 `jev-1.14.0`，官方审查请求由 `jev-1.14.0` 回答，放行场景判为低风险放行（0.46 秒）、外发凭据场景判为高风险拒绝（0.47 秒），DeepSeek Flash 两项仍正常；14 个目录模型全部通过路由回答，Key 轮换、坏 Key 分类、RPC 投影和 Claude CLI 通道无变化。直接请求 `/v1/systemone` 时 `jev-1.14.0` 返回 200，`jev-latest` 返回 `model_not_found`。设置卡片尚未在 DSH 桌面端界面中实际查看。

在 DSH 插件管理中更新至 **1.4.9**，然后重新打开 DSH 加载新版。
