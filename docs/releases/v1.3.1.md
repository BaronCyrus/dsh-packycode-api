# v1.3.1：余额刷新不再请求无效的账户接口

余额刷新只读取每个 Key 自己的额度，不再请求 PackyCode 按 Key 返回、插件却当成账户账单的 billing 接口。

- **原因**：PackyCode 的 `/v1/dashboard/billing/*` 只返回发起请求的那个 Key 自己的数字：额度是这个 Key 的总额，`total_usage` 是它自己的已用金额且单位是美分，不限额 Key 的额度是固定占位值 100000000。插件把它们当成账户账单，单位也读错了；这些数字早已不在界面上显示，却让每次刷新多等两个请求。
- **修复**：余额读取只请求每个 Key 的额度接口 `/api/usage/token/`，设置页和输入框显示的剩余、已用与合计不变；设置页接口不再返回账户字段，Key 的余额读取被拒（402/403）时也不再报成账户读取失败。
- **不限额 Key**：API Key 读不到账户余额，账户余额只在需要登录的 PackyCode 控制台里。不限额 Key 继续显示「不限额」和它自己的已用金额，账户余额请在控制台查看。

验证：393 项测试、两份构建和发布包检查通过。实测构建后的余额读取对每个已存 Key 只请求一次额度接口，不限额 Key 显示为不限额；全模型路由、Key 轮换与设置页接口的实测检查均正常。未重启 DSH。

在 DSH 插件管理中更新至 **1.3.1**，然后重新打开 DSH 加载新版。
