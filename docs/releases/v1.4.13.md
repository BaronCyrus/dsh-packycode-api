# v1.4.13：修复 Claude Code 历史重建时的空 system 错误

Claude CLI 通道默认启用官方网关兼容设置，避免从 DSH 历史重建会话时出现 `system content must contain at least one block`。

- **修复历史重建失败**：Claude Code 2.1.325 的逐轮 effort 协议会在重建历史时加入正文为空的 system 控制消息，网关不兼容时返回 400；短对话同样可能触发。插件现在直接在隔离子进程中设置兼容开关，无需手动修改 settings。
- **保留推理档位**：顶层 effort（包括 `max`）、adaptive thinking 和普通非空 system 消息保留；开关同时关闭实验性 context management、结构化输出格式、task budget、部分工具 schema 字段及 MCP 工具搜索，具体范围已补充到两份 README。
- **保持配置隔离**：只调整插件启动的 Claude Code 环境，不修改个人或项目的 Claude 配置，不改变 Key 分组路由、工具授权、计划审批或提问流程。

验证：582 项测试、两份构建和发布包检查通过。官方 Claude Code 2.1.325 在本机模拟接口上的新建、恢复、短历史重建和 743 条消息的长历史重建均通过，不再发送逐轮 effort beta 或空控制消息。使用插件保存的 `cc` Key，对 Fable 5.2、Opus 5.5、Sonnet 5.5、Haiku 5.5 跑完读取、编辑授权、拒绝、计划审批、提问、图片和标题共 28 个真实场景：首轮 22 个通过，6 个遇到连接重置，单独复测全部通过；客户端异常和反滥用拒绝均为 0。另测 Opus 5.5 `max` 档新建、恢复、短历史重建，三轮均返回正确结果及 HTTP 200。未重放原始私有长会话，未操作桌面 GUI。

在 DSH 插件管理中更新至 **1.4.13**，然后重新打开 DSH 加载新版。
