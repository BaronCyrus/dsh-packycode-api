## 压缩结束后接回正常回复，并告诉用户正在等待什么

长对话里，T3 把「正在压缩上下文」显示为一个有开始和结束的项目，能区分成功、失败和用户中断。CLI 给出压缩前后 token 数时才填数字。插件已经识别 `compacting` 并跳过内部摘要的流，但 `status: null` 加 `compact_result: failed` 本身不会清掉这个标记。 [T3 压缩结束状态](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L10930-L10973) · [T3 压缩前后计数](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L11049-L11074) · [插件处理状态和消息流](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-cli-session.js#L413-L469)

离线核对时，模拟 CLI 先报告正在压缩，再报告失败，紧接着发送正常回答。传输层跳过了这段回答。补上一条 `requesting` 后，下一段回答才被接收。这个结果依赖帧的顺序，还需用支持的 CLI 版本确认实际出现的情形。T3 的用例还区分了带 `permissionMode` 的空状态通知和真正的压缩结束。 [T3 对不同空状态帧的测试](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.test.ts#L10786-L10835)

建议先修正结束判定，再把「正在压缩」「压缩完成」「已中断」「压缩失败」作为当前会话的只读状态，首版可在现有对话插槽或会话诊断中呈现。状态不作为聊天消息回送 CLI。验收时检查压缩的内部摘要不占一个 DSH 模型步骤，紧随其后的正常回答恰好显示一次，取消时不会留下忙碌提示。 [插件现有对话插槽](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/client.jsx#L1055-L1065) · [会话诊断的字段范围](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/diagnostics.js#L2-L14)

## 写文件完成后展示实际改动

Bash 已有终端卡，Edit、MultiEdit 和 Write 也已有 diff 预览。写入完成后，适配器从 `tool_result` 只取内容和错误状态，成功卡片随后又展示调用参数。以 Write 覆盖已有文件为例，卡片知道写入的新内容，旧内容是 `null`，用户看不出原来哪几行被替换了。T3 在一条工具结果能明确关联时，读取 Claude 返回的 `structuredPatch`，显示带上下文的实际改动。 [插件的调用与结果卡片](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-agent-tools.js#L46-L80) · [插件读取结果的入口](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-cli-session.js#L517-L525) · [T3 处理多结果归属](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L4264-L4286) · [T3 的补丁用例](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.test.ts#L15052-L15120)

调用前仍显示预览。建议在成功后把能够明确归属于该调用的补丁放入 DSH 工具的展示元数据，只在卡片里渲染。可复用插件生图工具已有的 `output.presentationMeta` 路径。旧 CLI 或本条结果缺少补丁时标明「调用预览」，失败和拒绝则保留真实结果。验收分别看新建文件、覆盖旧文件、一帧返回多次调用及重新打开聊天，确保补丁属于正确的操作，同一段 diff 没有再次进入模型上下文。上游是 SDK 帧，原始 stdio 在插件支持的 CLI 版本上能提供哪些字段，实施前要核对。 [T3 补丁转换](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L3892-L3927) · [插件现有展示元数据用法](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/images.js#L282-L301)

## 输入框显示当前模型会用哪把 Key

## 用会话位置判断能否续接

T3 在 Claude 支持的分叉和回退路径上记录原生消息游标，并核对游标所属的线程和轮次。插件已有重新使用进程、按 CLI 会话 ID 恢复以及从 DSH 历史重建三条路径。当前对存活进程的判断主要比最后一条助手回复的文本和工具调用 ID，跨进程恢复也用到这个指纹。 [T3 的分叉位置](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L2749-L2786) · [插件存活进程的续接条件](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-cli-transport.js#L142-L163) · [重启后的判断](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-cli-transport.js#L360-L391)

离线调用插件的续接函数，把同一会话的前文分别设为「记住红色」和「记住蓝色」，助手都答「记住了」。继续追问时，两份输入都会选择复用原进程，交给 CLI 的只有新问题。现有回归用例同时改变了旧提问和助手回复，因此能触发重建。这里确认的是续接函数的行为，桌面端具体哪些编辑路径会保留同一个会话 ID，仍需端到端核实。 [指纹的构成](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-cli-transport.js#L105-L111) · [现有重启与编辑用例](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/tests/claude-cli-transport.test.mjs#L403-L448)

如果 DSH 提供稳定的历史位置，建议保存该位置与 CLI 会话的对应关系。也可以对已经交给 CLI 的那段历史计算摘要，排除 DSH 自己注入的提示，识别图片和工具结果。前缀确实改变时走已有的历史重建。验收覆盖普通追问继续复用，同尾句但前文不同走重建，重启后遵守同一规则，以及中断后已完成的工具调用不会重复执行。 [插件历史重建](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-transcript.js#L51-L86) · [已有中断恢复用例](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/tests/claude-cli-transport.test.mjs#L516-L553)

## 下一步可以做的小改动

- **把 Claude 的待办显示成一张可折叠清单。** 目前一条只有编号和完成状态的更新，卡片标题只有 `TaskUpdate`。首版可以直接显示「任务 #5 已完成」，拿到任务标题时一起展示。T3 能把原生 `TodoWrite` 和成功的 `TaskCreate`、`TaskUpdate`、`TaskList` 事件归并成步骤。用当前会话实际收到的原生任务按编号合并，点击展开详情。任务仍由 Claude 管理，DSH 的计划审批继续使用现有入口。旧版本未提供足够信息时沿用普通工具卡。 [T3 待办投影](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L11558-L11565) · [T3 成功后更新清单](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L11648-L11694) · [插件工具卡的通用分支](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-agent-tools.js#L60-L68)
- **审批时看得到完整命令。** 顶层 Bash 的工具卡保存了命令，但审批原因会压平换行并截到约 300 字。没有对应顶层卡片的子调用只能通过 DSH 审批服务看到这段原因。可给审批详情增加按需展开、保留换行的命令和 CLI 提供的原因，并复用脱敏。建议分别验收长命令的尾部能否读全，以及在完全访问模式下 CLI 仍主动要求确认时，DSH 能否按本轮预设处理。T3 对后者有专项测试，插件当前假 CLI 未覆盖这类普通工具提示。具体决定继续交由会话预设下的 DSH 服务。 [插件审批摘要](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-agent-tools.js#L28-L48) · [子调用审批](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/src/claude-agent-tools.js#L282-L297) · [T3 原命令与审批标题](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts#L12384-L12412) · [插件的假 CLI 权限条件](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/tests/fixtures/fake-claude-agent.mjs#L101-L108) · [T3 的额外确认用例](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.test.ts#L951-L969)

## 哪些功能需要 DSH 配合

T3 的跨端审批、独立工作树和回退依赖它同时持有会话、仓库和客户端连接。单次写操作的卡片可以在插件里改进。要让 Claude 写入的文件也出现在 DSH 全局「文件改动」面板里，并支持统一撤销，则需要与宿主的文件变更记录接口一起设计。 [T3 工作区与连接归属](https://github.com/pingdotgg/t3code/blob/316c3256a3a09cef7ed68914ebe74c7183ac08e1/docs/internals/overview.md#L3-L18) · [插件的文件改动面板现状](https://github.com/BaronCyrus/dsh-packycode-api/blob/592696db58bbf858132e35ba1f15ccc1d4e377a6/README.md#L147-L149)
